# 网页结构

## 用户页面结构

页面以首页为入口，通过导航进入产品介绍、个性化库编译和硬件情况查看。独立管理入口维护公共知识库与系统状态。

### 首页

- 展示当前 3D 模型及硬件结构资料，提供蓝牙连接入口。
- 不设置完整实时数据面板，只显示蓝牙连接状态、兼容性提醒和必要的简要摘要。
- 提醒用户 ESP32 Deep Sleep 时无法由网页远程唤醒，需要通过外置按钮唤醒后再连接。
- 提醒用户 Web Bluetooth 的浏览器、系统和授权要求。
- 提供侧边快速跳转入口：
  - 产品介绍页面。
  - 个性化库编译页面。
  - 硬件情况查看页面。
- 首页应直接显示蓝牙连接状态，让用户知道是否已经连接 ESP32-C3。

### 硬件情况查看页面

- 蓝牙未连接前不显示设备数据，只提示用户连接蓝牙。
- 蓝牙连接后先检查握手是否正常。
- 握手成功后展示设备实际报告的：
  - 设备 ID。
  - 固件版本。
  - 当前模式。
  - 植物配置。
  - 采样时间、温度、湿度、土壤 ADC、雨量 ADC、浇水需求值；当前通信固件返回空采样时说明原因。
- 有采样时按采样身份去重绘制需求趋势，标注最近读取和采样年龄。
- 按需通过 BLE 分页读取设备历史；设备未提供历史时显示空状态。
- 模式切换、读回配置、重启及恢复出厂集中在设备页，依握手能力开放。

### 个性化库编译页面

- 页面结构模仿 iOS 设置的分组面板。
- 用户输入项包括但不限于：
  - 植物。
  - 地点/国家。
  - 花盆或地栽方式。
  - 花盆大小。
  - 光照条件。
  - 室外、室内或温室种植位置。
  - 供水装置、储水量及需要时的实测流量。
  - 水源描述。
- 后端根据用户输入、内部权重库和第三方 API 资料生成个性化配置。
- 审核植物来源及参考范围后，结果页展示适配依据；无审核范围时显示“暂无适配依据”。
- 浏览器经 BLE 发送配置，设备以保存回执确认。回执未到时连接原设备读回核对。
- 此页提供生成、预览、发送、导入和导出；配置留在页面内存，用户主动导出的 JSON 是副本。

### 产品介绍页面

- 用简短语言介绍产品用途和工作原理。
- 展示 3D 分解模型、10-01 PCB 工程图、工作原理和使用步骤；将当前通信固件与整机目标能力区分说明。

## Flask 平台结构

代码中的 Flask 平台包含：

- `app.py`：路由、数据库、临时配置生成 API 与系统监控 API。
- `templates/index.html`：前端页面模板。
- `engine/rules.py`：参数推导。
- `engine/validation.py`：配置边界校验。
- `engine/plant_library.py`：植物来源与审核字段的结构迁移。
- `knowledge_base/plants.json`：首次初始化的工程建议条目；运行数据存于 SQLite `library_documents`。
- `static/js/admin-app.js`：管理员植物条目和审核记录维护。

## 数据流页面结构

典型页面流程：

1. 填写场景。
2. 执行分析。
3. 查看推荐参数。
4. 生成临时配置包。
5. 前端通过 BLE 下发给 ESP32。
6. 查看 ESP32 校验和写入结果。

“个性化库编译页面”应把上述流程合并成普通用户可理解的连续配置体验，不把内部参数推导和配置结构暴露得过重。

## ESP32 设备交互结构

浏览器前端需要把 BLE 设备交互组织成清晰状态：

- 未连接：提示用户唤醒设备并连接蓝牙。
- 已连接未握手：显示连接中或重新握手。
- 握手成功：允许读取状态、读取历史、下发配置。
- 写入中：显示发送、校验、保存进度。
- 设备明确拒绝：显示失败原因。
- 保存回执未到：记录待核对目标及版本，连接原设备读回后确认。
- 设备确认保存后状态刷新失败：保留已保存结论，提示重新连接核对状态。
- 设备休眠或断开：提示用户重新唤醒并连接。

## 前端约束

- Web Bluetooth 兼容性要在首页提醒。
- 高频读取会增加 ESP32 唤醒期间负载，应限制刷新频率。
- 配置写入、模式切换、重启、恢复出厂等操作需要清楚展示确认和结果。

## 后续整理建议

- 将 BLE 交互能力与 Flask API 分两张表维护。
- 将蓝牙交互能力单独维护为一张表。
- 将配置 JSON 示例固定在 [[132-协议使用]]。
- 网页 UI 细节放本页，接口细节放 [[133-API服务]]。
