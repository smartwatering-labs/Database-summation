# 各部协同方式

## 协同对象

| 对象 | 主要作用 |
|---|---|
| 用户 | 提供植物、地点、硬件实际情况和运行目标。 |
| 浏览器前端 | 提供首页、三类子页面、蓝牙连接、状态展示和配置入口。 |
| Flask 平台 | 把用户场景转为临时配置包，并提供系统健康监控。 |
| ESP32 固件 | 3.6.0 已实现 BLE 配置、采样、质量与事件、脉冲浇水保护、保存、校时和休眠；编译与主机测试通过，接板后进行烧录、标定和实物验收。 |
| 传感器 | 提供土壤、雨量、空气温湿度数据。 |
| 执行器 | 水泵浇水，舵机擦拭雨量传感器。 |
| Obsidian 资料库 | 记录项目事实、边界、冲突和后续改动。 |

## 场景到参数

1. 用户在个性化库编译页面填写种植场景。
2. Flask 在当前请求中处理场景，不把用户配置作为长期记录保存。
3. Flask 匹配植物、栽培方式、地区环境权重库，并按需要调用第三方 API 补充海拔、降水、湿度、日照等资料。
4. `engine.rules.derive_parameters()` 根据知识库和环境资料推导参数。
5. 生成临时配置包并返回给前端。
6. 前端展示季节间隔、单轮水量、水箱续航和推荐模式；具备能力的设备使用 2.0 配置，包含目标 ID 和最短浇水间隔。用户可选用通过校验的真实准备期温湿度与标定流量辅助生成。

## 参数到代码

第一阶段不把网页流程设计为代码版本管理系统。后端主要生成 ESP32 可读取的配置包；如果后续需要固件代码生成，应作为独立功能再设计。

## 参数到设备

主线流程：

- 蓝牙配置：用户设备与 ESP32-C3 蓝牙连接，握手后直接下发配置包。

后端不直接连 ESP32，前端负责 BLE，后端负责生成配置。设备侧交互集中在蓝牙读写能力上。

## 设备数据到网页：整机联调目标

1. 新固件按经实测确定的周期唤醒并读取传感器。
2. 固件保存最新采样值和一周以内历史记录。
3. 用户打开硬件情况查看页面并连接蓝牙。
4. 握手成功后，网页实时显示设备信息、传感器数据和浇水需求值。
5. 用户点击近期数据查看时，网页读取历史记录并转译成可理解内容。

## 设备运行闭环：整机联调目标

1. ESP32 启动并加载 NVS 配置。
2. 读取传感器数据。
3. 根据算法计算需求值。
4. 若下雨或数据无效，则需求归零。
5. 若需求达到阈值且固件控制间隔满足，则启动脉冲浇水。
6. 写入日志。
7. 进入 deep sleep 等待下次唤醒。

## 文档协同方式

后续每次改动建议同步记录：

- 软件改动写入 `300-历史改进/<日期>/芯片程序改动.md` 或 `网页改动.md`。
- 硬件改动写入 `硬件改动.md`，并同步更新 `120-浇水机器硬件`。
- 不确定内容写入 `600-代办事项`，不要混入确定事实文档。

## 硬件协同

上板负责传感器供电与采集、执行器控制信号；下板负责电源连接、水泵驱动和舵机接口。固件按[[121-设备与引脚]]操作设备，按[[122-运行与待定参数]]安排启动、采样和休眠。
