# 网页结构

## 用户页面结构

页面以首页为入口，侧边提供快速跳转到三个子页面。

### 首页

- 展示 Three.js 可自由转向的硬件 3D 模型；模型未完成前可使用硬件图片占位。
- 不设置完整实时数据面板，只显示蓝牙连接状态、兼容性提醒和必要的简要摘要。
- 提醒用户 ESP32 Deep Sleep 时无法由网页远程唤醒，需要通过外置按钮唤醒后再连接。
- 提醒用户 Web Bluetooth 存在浏览器兼容限制，备用方案暂时不定。
- 提供侧边快速跳转入口：
  - 产品介绍页面。
  - 个性化库编译页面。
  - 硬件情况查看页面。
- 首页应直接显示蓝牙连接状态，让用户知道是否已经连接 ESP32-C3。

### 硬件情况查看页面

- 蓝牙未连接前不显示设备数据，只提示用户连接蓝牙。
- 蓝牙连接后先检查握手是否正常。
- 握手成功后实时展示：
  - 设备 ID。
  - 固件版本。
  - 当前模式。
  - 植物配置。
  - 温度、湿度、土壤 ADC、雨量 ADC、浇水需求值。
- 保留需求值图表画布逻辑。
- 提供“近期数据查看”按钮，展开后读取 ESP32 一周以内历史数据，并转译为用户能理解的内容。

### 个性化库编译页面

- 页面结构模仿 iOS 设置的分组面板。
- 用户输入项包括但不限于：
  - 植物。
  - 地点/国家。
  - 花盆或地栽方式。
  - 花盆大小。
  - 光照条件。
  - 是否无人值守。
  - 水源描述。
- 后端根据用户输入、内部权重库和第三方 API 资料生成个性化配置。
- 蓝牙连接可用时，把处理后的配置发给 ESP32 并修改其运行数据。
- 同页提供模式控制：切换 `DISPLAY`、`PREPARE`、`LONGRUN`。
- 同页提供配置管理：上传、下载、导入、导出配置。
- 同页提供设备操作：重启、恢复出厂。

### 产品介绍页面

- 用简短语言介绍产品用途和工作原理。
- 暂时可以放随机图片或留空占位，后续根据产品资料完善。

## Flask 平台结构

代码中的 Flask 平台包含：

- `app.py`：路由、数据库、临时配置生成 API 与系统监控 API。
- `templates/index.html`：前端页面模板。
- `engine/rules.py`：参数推导。
- `engine/code_generator.py`：旧方案或后续扩展中的固件生成能力；第一阶段主线不依赖代码版本管理。
- `knowledge_base/plants.json`：植物知识库。
- `knowledge_base/locations.json`：地点知识库。
- `templates/firmware_template.ino`：旧方案或后续扩展中的固件模板。

## 数据流页面结构

典型页面流程：

1. 填写场景。
2. 执行分析。
3. 查看推荐参数。
4. 生成临时配置包。
5. 前端通过 BLE 下发给 ESP32。
6. 查看 ESP32 校验和写入结果。

“个性化库编译页面”应把上述流程合并成普通用户可理解的连续配置体验，不把内部参数推导和配置结构暴露得过重。

## ESP32 设备交互结构

浏览器前端需要把 BLE 设备交互组织成清晰状态：

- 未连接：提示用户唤醒设备并连接蓝牙。
- 已连接未握手：显示连接中或重新握手。
- 握手成功：允许读取状态、读取历史、下发配置。
- 写入中：显示发送、校验、保存进度。
- 写入失败：显示固件返回的失败原因。
- 设备休眠或断开：提示用户重新唤醒并连接。

## 前端约束

- Web Bluetooth 兼容性要在首页提醒。
- 高频读取会增加 ESP32 唤醒期间负载，应限制刷新频率。
- 配置写入、模式切换、重启、恢复出厂等操作需要清楚展示确认和结果。

## 后续整理建议

- 将 BLE 交互能力与 Flask API 分两张表维护。
- 将蓝牙交互能力单独维护为一张表。
- 将配置 JSON 示例固定在 [[132-协议使用]]。
- 网页 UI 细节放本页，接口细节放 [[133-API服务]]。

## 2026-09-09 网页首版实现

首页与三个用户子页面使用同一 Flask 模板内的 hash 导航，保持当前页面临时配置；刷新或关闭后清除。管理员监控为额外管理入口，不建立用户登录系统。

首页采用已有控制器参考图，产品页采用 PCB 资料图，明确标注非整机模型。个性化库编译页面采用分组表单与独立结果区；设备页面仅在握手成功后显示采样。模拟设备入口为显式选择，所有模拟状态有标记。

本轮优先功能实现，颜色与组件基础遵循项目根目录 `prototype/design.md`，后续可独立调整 `prototype/static/css` 和页面视图。实现与待联调范围见 项目中的 `prototype/docs/网页首版实现记录.md`。
