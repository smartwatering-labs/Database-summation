# 项目视觉设计规范

版本：1.3  
参考网站：[X Business](https://business.x.com/en)  
访问与分析日期：2026-09-09  
适用范围：本项目此后所有新增、改版页面及公共组件。

2026-09-23 更新：普通用户页面按用户要求增加工业极简视觉、蓝色重点色（#175CFF）、3D 模型的页面姿态与可中断过渡、半透明详情窗口和渐进揭露。既有网格和业务功能保留，正文说明可收起到详情；管理端保持原样。此项更新优先于下文旧版颜色与圆角规则，具体实现及模型替换约定见 [3D 展示说明](docs/model-presentation.md)。

本文提炼视觉规则，不复用参考站的品牌标识、营销文案、客户案例、图片或业务内容。后续页面应先阅读本文，再确定布局与组件；相同语义必须使用相同的颜色、字阶、间距和状态。

## 分析依据与使用方式

- 分析对象是访问时跳转到的英文首页，不代表参考站全部内页。
- 通过公开页面 HTML、原站 CSS／字体／脚本、浏览器计算样式和截图交叉核对。浏览器首次直连中断后，以请求取得的同一原站 HTML 响应加载页面，其他资源仍由原站提供；没有重建或修改其布局。
- 主要视觉检查视口为桌面 1440 × 1000、手机 390 × 844；另检查了 767、768、1024、1280、1920px 宽度。上述宽度均未观察到整页横向溢出。
- 已验证侧栏分组展开、移动菜单打开与 Escape 关闭、按钮悬停、浅色／深色主题切换。动效时长同时参考原站样式声明；未验证表单提交、跳转后的页面或全部键盘流程。
- 首轮截图中部分动态图形尚未进入展示状态，已等待并重新核对。空白媒体容器不是应当复用的视觉设计。
- 每节的“原站观察”描述本次证据；“项目规则”才是本项目的执行标准。项目适配值属于设计决策，不应描述成原站测量值。

## 1. 页面整体布局

### 原站观察

页面由左侧纵向导航与右侧长内容区组成。内容围绕同一条起始线组织，以大标题、宽幅图形、错位图文、案例、表单和页脚形成滚动节奏。段落之间使用大量空白与极细水平线，不依赖每段一个外框。

构图带有编辑式排版特点：标题靠左，部分说明放在右半区；局部出现小标签在左、大标题在右的布局。信息密度在展示区较低，在导航、表单与元信息处较高。

### 项目规则

- 采用“导航区 + 内容区”的统一页面骨架；主内容的标题、分隔线、图形和列表共享容器边界。
- 展示型页面按“页面主题 → 图形或关键内容 → 说明与行动 → 细节模块”组织。每个区域只突出一个主要信息。
- 工作台、数据列表和设置页继承同一网格、字体、颜色与组件，不强制放置宣传型 Hero 或冗长页脚。
- 用字号、留白、对齐和背景明度建立层级；不要把所有内容都装进带阴影的大圆角卡片。
- 不使用原站的栏目名称、业务顺序或营销内容作为本项目的信息架构。

## 2. Header / Navigation

### 原站观察

- 桌面导航是宽 208px 的 sticky 侧栏，占据视口高度，内边距 24px；上方为品牌／站点入口，下面为纵向导航，账户入口位于底部。
- 侧栏背景与页面一致，无明显厚重分界；主项为紧凑文字，未选中项呈灰色，当前项为高对比文字。
- 分组点击后纵向展开，箭头改变方向；子项缩进，并用细竖线辅助表达层级。
- 低于 768px 时改用固定顶部栏，高 64px；左侧品牌，右侧账户入口与圆形菜单按钮。栏背景带透明度和轻微模糊。
- 手机菜单铺满顶部栏下方的可用屏幕，导航文字明显放大，菜单按钮切换为关闭图标。

### 项目规则

- ≥768px 使用宽 208px、占满视口高度的固定侧栏，内边距 24px；长菜单允许独立滚动。工作区使用本项目名称与标识。
- 半透明圆角指示框只标记当前页面，不跟随鼠标悬停或键盘焦点。切换页面时由持续的逐帧插值驱动，沿同一轨迹平滑移向新页面；指示框不拦截点击，减少动态模式下立即到达目标。
- 桌面导航文字采用 14px／20px，字重 500；行高区域至少 36px。当前项使用主文字色，普通项使用次文字色，悬停可叠加轻灰背景。
- 子项使用 12–16px 缩进，必要时增加 1px 分组竖线；最多展示两层导航。
- <768px 使用 64px 顶栏，内容预留同等顶部空间；左右边距 16–18px。菜单按钮触控区域至少 44 × 44px。
- 移动菜单文字 20px／28px，行触控高度至少 44px；支持关闭按钮、Escape、焦点回到触发按钮，并防止背景内容随菜单滚动。
- 账户操作在不同设备上保持可发现性。导航文案过长时允许合理换行，不挤压主内容。

## 3. Hero section

### 原站观察

Hero 依次为左对齐大标题、通栏线性图形、右半区的简短说明与双按钮。桌面标题实测 48px／52px、字重 500；并非整屏巨字或居中海报。图形使用浅灰底、细实线／虚线、小节点与数据标签，整体克制。

1440px 视口下，图形宽约 1120px、高约 407px；手机下约 358 × 215px，图形会裁切、调整展示范围。手机说明和按钮回归左对齐，紧接图形；大标题仍保留较强视觉份量。

### 项目规则

- 仅展示首页或确有说明需求的页面使用完整 Hero。功能页采用紧凑的标题、说明和操作区。
- 桌面 Hero 顶部留白 80px，标题之后间隔 24px 放置媒体；媒体之后间隔 24px 放置说明，说明下方留 16–24px 放按钮。
- 桌面标题最多占主网格 6 列，说明与行动区可占右侧 4 列；手机全部占满内容宽度。
- 图形应表达本项目的流程、状态或数据关系，优先使用细线、节点、简单几何与中性底色。不得把装饰性数据伪装成实际业务数据。
- 宽幅图形桌面建议接近 2.75:1，手机接近 5:3。关键文字和数据标签在窄屏需重排，不能因裁切而丢失。
- 只配置一个主要行动；可添加一个次要行动。不要用大量徽章、多个同权重按钮或背景装饰争夺标题注意力。

## 4. Typography

### 原站观察

实际加载的字体为 xVF 正文与 xVFDisplay 展示字体。标题以中等字重配合紧凑字距形成轮廓，正文则轻巧紧凑。主标题 48/52px，主要区块标题 32/36px，桌面正文与导航常用 13/20px；手机 Hero 说明增至约 16/20px。部分标题将前半句设为黑色、后半句设为灰色。

### 项目规则

不直接引入原站字体文件。采用系统无衬线字体体系，中文优先 PingFang SC、Microsoft YaHei、Noto Sans CJK SC，西文使用 system-ui；全站保持一致。

| 文本角色 | 桌面字号／行高 | 手机字号／行高 | 字重 |
| --- | --- | --- | --- |
| 展示首页主标题 | 48／56px | 36／44px | 500–600 |
| 功能页标题 | 32／40px | 28／36px | 500–600 |
| 区块标题 | 32／40px | 28／36px | 500–600 |
| 小标题、重点数值 | 24／32px | 22／30px | 500–600 |
| 正文、表单输入 | 16／26px | 16／26px | 400 |
| 导航、按钮、卡片标题 | 14／20px | 15／22px | 500 |
| 标签、元信息 | 12／18px | 13／20px | 400–500 |

- 上表为适应中文阅读而确定的项目值，不机械继承原站的小号正文。
- 英文大标题可用 -0.01em 字距；中文默认正常字距，不通过过度压缩实现紧凑感。
- 一个页面只有一个一级标题；语义层级与视觉层级各自正确，不能因为原站某处标签较小就使用错误的标题层级。
- 正文段落建议控制在约 30–40 个汉字行宽；较长说明采用限制宽度的阅读区。
- 双色标题只在前后语义适合分层时使用；次要部分仍须清晰可读。避免整页粗体与全大写。

## 5. Color system

### 原站观察

默认浅色界面以白、黑与低饱和灰为主；蓝色虽存在于样式变量和焦点环中，却不是首页大面积主色。深色模式主要将页面与文字反转，并使用深灰承载媒体。彩色主要来自局部图形和品牌素材。

原站浅色主背景为 #FFFFFF，次背景为 #F2F2F2，主文字 #000000，次文字约黑色 60% 不透明度，普通边框约黑色 10%。暗色主背景 #000000、次背景 #141414、主文字 #FFFFFF、次文字约白色 60%。

### 项目规则

按语义使用颜色，默认以浅色作为设计基线。下表为统一项目色值；暗色列用于后续需要提供主题切换的页面，不要求本轮实现主题功能。

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| background | #FFFFFF | #000000 | 页面底色 |
| surface | #F2F2F2 | #141414 | 媒体底、次级内容面 |
| surface-strong | #EBEBEB | #262626 | 更强的局部背景 |
| text-primary | #000000 | #FFFFFF | 标题、正文、关键数据 |
| text-secondary | #666666 | #999999 | 说明、次要导航 |
| border | rgba(0,0,0,0.10) | rgba(255,255,255,0.10) | 细分隔线、输入边界 |
| border-hover | rgba(0,0,0,0.20) | rgba(255,255,255,0.20) | 悬停边界 |
| border-active | rgba(0,0,0,0.30) | rgba(255,255,255,0.30) | 活动输入边界 |
| primary-fill | #000000 | #FFFFFF | 主按钮底色 |
| primary-label | #FFFFFF | #000000 | 主按钮文字 |
| focus-ring | #1D9BF0 | #1D9BF0 | 键盘焦点 |

- 主按钮的 hover／pressed 使用主色 80%／70% 不透明度；次按钮默认、hover、pressed 使用相应前景色 5%／10%／20% 叠加于浅色背景。深色次按钮从白色 10% 起步。
- 不额外引入大面积蓝紫渐变、荧光装饰或多品牌色。彩色只服务于业务状态、真实图像与少量必要强调。
- 项目状态色扩展：成功 #15803D、警告 #92400E、错误 #B91C1C、信息 #0369A1；浅色背景分别可用 #F0FDF4、#FFFBEB、#FEF2F2、#F0F9FF。这些是项目新增语义，非原站取样。
- 状态必须同时有文字或图标，不能只靠颜色；深色状态组合需单独验证，不能直接套用浅色组合。
- 正文对比度至少 4.5:1，大字至少 3:1；重要状态边界需清晰可辨。细装饰分隔线与输入框的唯一识别边界应区别处理。

## 6. Spacing

### 原站观察

原站以 4px 为基础单位，8、12、16、24、32、56、80、100、120px 等间距反复出现。桌面大区块常有 80px 顶部与 100–120px 底部留白；移动端显著收缩。主网格间隙为 16px，表单列间距 12px、行间距 28px。

### 项目规则

| 用途 | 标准值 |
| --- | --- |
| 最小微调、图标细节 | 4px |
| 图标与文字、标签与控件 | 8px |
| 紧凑按钮组、小型信息组 | 12px |
| 默认网格沟槽、手机页边距 | 16px |
| 面板内边距、图文内部间隔 | 24px |
| 子区块间隔 | 32px |
| 手机展示区块上下留白 | 40–56px |
| 桌面展示区块顶部留白 | 80px |
| 桌面展示区块底部留白 | 80–120px |

- 相同组件、相同层级必须复用同一间距，不能逐页随意微调。
- 功能页主区域间距采用 24–32px，避免照搬宣传页的 120px 空白降低操作效率。
- 分隔线上下的留白是分区节奏的一部分，不把线紧贴标题或按钮。
- 布局收缩首先减少区块留白和改变列数，再考虑字号调整；不通过缩小触控区域节省空间。

## 7. Card design

### 原站观察

案例卡片采用开放式结构：顶部是小型分类／日期，中央是大块矩形媒体，下方为标题、灰色说明和小胶囊行动。卡片外围没有统一的厚边框、圆角外壳或常驻阴影。

桌面案例网格采用 1:2:1 的列宽，中间案例获得更多展示面积；在本次悬停核对中比例保持不变，不应误写成 hover 扩张效果。功能介绍更像“图形 + 编号 + 文字”的组合，而非仪表盘式方盒。动态内容墙另有轻量白色内容面及错位堆叠。

### 项目规则

- 展示卡片默认开放式：媒体 → 标题 → 说明 → 行动；元信息需要时放在媒体上方。所有子元素左对齐。
- 同一组媒体保持一致高度；图片根据内容选 contain 或 cover，标识类图片优先 contain，不能拉伸。
- 桌面常规卡片间距 24px，手机单列纵向间距 32–40px。媒体与标题间距 12px，标题与描述间距 8px。
- 卡片使用固定网格。展示页存在明确的重点案例时，可使用 1:2:1 的比例突出中间项；普通同等级内容采用等宽列。触控端保持稳定单列，关键内容无需 hover 才能阅读。
- 功能性面板可使用 1px 边框、白色或次级背景、24px 内边距，仍保持平面感。可操作元素必须有明确的按钮、链接或完整可点击区域语义。
- 表单输入框与卡片共用中性配色：标签在外部上方，输入高度 44px、水平内边距 16px；错误提示紧邻对应字段，不能只改变边框颜色。

## 8. Button design

### 原站观察

主按钮为黑底白字，次按钮为浅灰底黑字，账户／语言入口可使用细描边。按钮形状为胶囊，常带紧凑文字。Hero 主按钮实测桌面高 24px、手机高 36px；账户入口约 32–36px。主要 hover 是颜色变化，默认过渡约 150ms。

### 项目规则

| 角色 | 外观 | 高度与水平内边距 |
| --- | --- | --- |
| 主要行动 | 主按钮底色 + 反色文字 | 桌面 40px／20px；手机 44px／20px |
| 次要行动 | 轻灰背景 + 主文字 | 与同组主按钮一致 |
| 描边行动 | 透明背景 + 1px 普通边框 | 40–44px／16px |
| 紧凑辅助行动 | 浅灰或透明底 | 桌面视觉高度 32px；触控区域至少 44px |
| 图标按钮 | 圆形，图标 18–20px | 44 × 44px 触控区域 |

- 采用完整胶囊圆角，文字居中，字重 500；按钮组间距 12px。
- 同一操作组只有一个实心主按钮。按钮文字表达动作，图标不能替代必要的文字解释。
- hover 改变填充明度；pressed 再增加一级变化；键盘 focus-visible 提供 2px 焦点环。
- disabled 使用约 50% 不透明度并禁止操作；loading 保持尺寸、显示进度反馈，防止重复提交。
- 按钮宽度按内容自适应；手机空间不足时换行或纵向排列，不能挤压文字或让页面横向滚动。
- 项目扩大了原站紧凑按钮尺寸，以适应中文与触控操作。

## 9. Border radius

### 原站观察

大型媒体、区块与案例图片主要为直角；操作按钮为完整胶囊。输入框和局部小组件有轻度圆角。原站字段基础圆角为 9px；支持 squircle 的浏览器会通过形状适配系数得到约 16.2px 的计算半径，因此不能将单次读数当成全站统一圆角。

### 项目规则

| 对象 | 圆角 |
| --- | --- |
| 页面区块、宽幅媒体、展示案例图片 | 0px |
| 小型嵌入面板、菜单面板 | 8px |
| 输入框、选择器、业务面板 | 8–10px，全站统一选型 |
| 按钮、状态胶囊 | 9999px |
| 头像、圆形图标按钮 | 50% |

优先使用普通圆角以保持跨浏览器一致性。不要求复刻 squircle；禁止所有容器统一变成 20–32px 的大圆角。

## 10. Shadows

### 原站观察

大多数区块、导航、媒体与常规按钮没有阴影，层次主要来自灰色底面、细线与留白。滚动后出现的浮动行动条有明显但柔和的投影，实测为 0 8px 16px、黑色 20% 不透明度；阴影属于悬浮交互层的例外。

### 项目规则

- 普通卡片、媒体、侧栏和按钮默认 shadow: none。
- 只有下拉层、弹窗、浮动操作条等脱离文档流的元素使用阴影。
- 统一轻浮层投影参考值：0 8px 24px rgba(0,0,0,0.12)；需要更明确层级的弹窗可用 0 12px 32px rgba(0,0,0,0.16)。这两项是项目参数。
- 深色浮层优先增强背景明度与细边框，避免仅依赖黑色投影。
- 阴影不可作为卡片 hover 的默认反馈，不使用彩色光晕或多层厚重投影。

## 11. 页面宽度和 Grid

### 原站观察

内容区上限为 1120px，采用 8 列等分网格，列间距 16px；站点另定义 1440px 的外层容器上限。两者用途不同，不能将 1440px 当成正文宽度。

1440px 视口下侧栏宽 208px，主内容从 x=264px 开始、宽 1120px。1920px 时内容仍为 1120px，居中于侧栏之外的可用区域，起始 x=504px。1280px 下主内容宽 1040px，侧栏之后保留 16px 基础内边距。

### 项目规则

- 桌面侧栏宽 208px，主区域填充剩余空间；正文容器在该区域内居中。
- 内容宽度取 min(1120px, 可用主区域宽度 − 32px)，保证至少 16px 左右内边距。全宽背景也必须对齐同一内部内容边界。
- 桌面采用 8 列主网格，沟槽 16px；典型结构为 4+4 图文分栏、6 列标题、8 列通栏。
- 三张案例采用独立三列网格，24px 间距；同级内容等宽，重点展示可选 1:2:1，不为了机械对齐而强塞进 8 列。
- 表单桌面可放在主网格右侧 4 列，表单内部两列、列间距 12–16px、行间距 24–28px；空间不足转为单列。
- 手机所有主模块占满可用宽度，内部可用 4 列辅助对齐。原站底层仍保留 8 列定义，但视觉上多数内容已经单列；项目不必保留这一内部实现细节。
- 表格列宽按信息需求决定，不强制跟随展示型栅格；必须在自己的容器内处理窄屏溢出。

## 12. Desktop / Mobile responsive behavior

### 原站观察

768px 是侧栏与顶部菜单的切换点；1024px 控制更充分的桌面图文分栏、大留白、表单双列和部分卡片布局。手机保留大标题，却显著增大部分说明文字和按钮。案例与表单顺序向纵向阅读靠拢，页脚链接重排为两列。

### 项目规则

| 宽度范围 | 导航 | 内容组织 | 间距重点 |
| --- | --- | --- | --- |
| <768px | 64px 顶栏 + 全屏菜单 | 主模块单列；表单单列；按钮可换行 | 16px 页边距，40–56px 展示区块留白 |
| 768–1023px | 208px 侧栏 | 保守分栏；表单优先单列 | 内容至少 16px 边距，32–56px 区块留白 |
| ≥1024px | 208px 侧栏 | 8 列主网格，支持图文并排和表单双列 | 80–120px 展示区块留白 |
| 宽屏 | 同上 | 正文最多 1120px，在主区域居中 | 增加外侧空白，字号不无限放大 |

- 调整的是阅读顺序与空间分配，不能简单按比例缩小桌面页面。
- 手机先显示主题和说明，再显示依赖说明的复杂交互；图形可以更换视图或裁切装饰区，关键数据不得消失。
- 768–1023px 的剩余内容宽度有限，不强行放三张卡片或双列长字段。
- 横向溢出只允许发生在明确的表格／时间轴容器，整页不得出现意外水平滚动。
- 固定底部操作条需计入设备安全区与内容底部占位，不能遮挡正文、输入框或键盘操作。
- 后续验收至少覆盖 360、390、768、1024、1440、1920px，以及长中文标题和浏览器缩放场景；其中 360px 与缩放属于待实施页面的验收要求，并非本次原站已测结果。

## 13. 动画和交互方式

### 原站观察

- 菜单：全屏层通过裁切区域变化展开，约 300ms；条目使用渐入与轻位移。桌面分组也有约 300ms 的展开过渡。
- 按钮与输入：按钮主要进行约 150ms 颜色变化；字段边框等状态约 200ms。
- 展示图形：使用细线、节点及局部图形的动态呈现，动效位于媒体容器内；不能仅凭 CSS 中存在动画名称认定所有区域都触发了相同动画。
- 内容墙：样式声明包含 90s 的线性横向循环与约 7s、3px 幅度的浮动；精细指针悬停或键盘聚焦时可暂停横向循环，减少动态模式下停止这些动画。
- 滚动时可出现底部居中的胶囊浮动行动条；这是局部行动入口，不是整页固定底栏。
- 页面提供系统／浅色／深色主题入口，主题切换改变背景、文字与组件颜色。

### 项目规则

| 交互 | 时长与方式 |
| --- | --- |
| 按钮、链接颜色状态 | 150ms，平滑颜色过渡 |
| 输入、选中、边框状态 | 200ms ease-out |
| 菜单、折叠组展开 | 250–300ms，轻位移或裁切展开 |
| 可选的一次性内容入场 | 400–600ms，透明度与最多 12px 位移 |
| 装饰性循环 | 缓慢、低幅度，仅用于展示媒体 |

- 默认页面内容立即可读。动画不能成为显示正文、关键数据或操作入口的前置条件。
- 功能页优先使用状态反馈，避免数据面板持续漂浮、数字无意义滚动或卡片反复进场。
- 图形动画与浮动操作条为可选模式，不要求所有页面启用；普通卡片悬停保持列宽和阅读位置稳定。
- Hover 与键盘焦点都要表达可交互性；重要信息在触控设备上必须直接可见。
- 尊重 prefers-reduced-motion：关闭循环、视差和位移动画；菜单可直接切换状态。持续展示运动应提供暂停方式。
- 浮动行动条仅在主行动离开视口后按需出现，保持与内容区对齐、预留遮挡空间；手机不照搬桌面的悬浮尺寸。
- 动效尽量局限于 opacity、transform，不让列表中的数据位置随意跳动。
- 主题切换不改变布局或信息结构；焦点、错误、禁用等状态在两种主题中都保持清晰。

## 全站执行与验收约束

1. 开始任何页面设计或实现前，先使用本文定义的页面骨架和语义 token；相同组件不得逐页出现不同视觉版本。
2. 优先复用：中性配色、208px 侧栏、1120px 内容上限、8 列网格、开放式卡片、胶囊按钮、细分隔线与分级留白。
3. 根据页面用途调整密度：展示页允许大留白，工作台与表单页优先可读性和操作效率；共享视觉规则保持一致。
4. 验收时检查长文本、空状态、加载、错误、禁用、焦点、窄屏与主题适配；不能只检查默认桌面截图。

6. 新增例外必须有业务或可用性原因，并先在本文记录，再扩展到页面中。不得仅为装饰引入另一套色彩、阴影或圆角语言。
