# 后端方案修订

## 已明确的方案边界

- 后端不直接连 ESP32，前端负责 BLE，后端负责生成配置。
- 用户配置是临时配置，不做登录系统，不保存配置历史版本。
- 用户退出浏览器或关闭当前页面后，当前配置状态应删除。
- 首页不做完整实时数据面板；完整实时数据放到硬件情况查看页面。
- 后端定位从“用户管理、设备管理”降级为“配置生成与系统监控”。
- 管理员密钥 `6767` 只是开发期临时方案，不作为最终安全方案。
- 固件中的 `configRevision` 只用于 ESP32 本地配置新旧校验，不代表后端保存配置历史版本。
- 清理旧通信方案混入内容，当前项目能力以浏览器前端通过 BLE 连接 ESP32 为准。

## 风险处理口径

- ESP32 Deep Sleep 时 BLE 不工作，网页不能远程唤醒设备，首页需要提示用户通过外置按钮唤醒。
- Web Bluetooth 存在浏览器兼容限制，首页先做提醒，备用方案暂时不定。
- BLE 加密与认证需要后续补齐密钥来源、nonce 过期、重放防护和配置签名方式。
- ESP32 Flash 历史数据使用固定环形缓冲区，只保留最近一周，按 2 小时唤醒估算至少 84 条。
- 后端不保存传感器历史和用户配置历史；系统日志只保存服务错误、外部 API 降级、接口耗时等维护信息。
- 外部 API 失败时使用静态地点库，并在结果中标记 `source: fallback`。

## 配置下发状态流

```text
生成配置 → 前端发送 → ESP32 校验 → 写入成功/失败 → 前端回报后端可选记录
```
