## 协议类型

当前代码中至少存在三类协议/数据格式：

- 网页蓝牙握手与数据传输协议：用于用户设备和 ESP32-C3 之间建立连接、同步数据、写入配置。
- 设备配置 JSON：包含 `revision`、`deviceModel`、`params`、`display` 等字段。
- Flask 平台临时配置生成 JSON：前端提交用户场景，后端返回可由前端通过 BLE 下发的配置包。

## 蓝牙协议目标

蓝牙协议需要覆盖四类动作：

1. 设备发现与握手：网页确认目标设备是浇水硬件，并取得设备 ID、固件版本、协议版本和 nonce。
2. 实时数据读取：ESP32 返回温度、空气湿度、土壤 ADC、雨量 ADC、浇水需求值、当前模式和植物配置。
3. 历史数据读取：ESP32 返回一周以内采样记录，网页负责转译为用户可读内容和图表数据。
4. 配置写入：网页把后端生成的个性化参数编码后发回 ESP32，固件校验后写入 NVS。

蓝牙传输结构应复用已有配置字段含义，避免新增第三套业务命名。若底层需要分包传输，应在协议层保留完整消息编号、总包数、校验值和失败重试规则。

## BLE 配置握手

常量：

```cpp
HANDSHAKE_PROTOCOL = "SWS-BLE"
PROTOCOL_VERSION = "1.0"
SECRET_KEY = "SWS2026C3"
DEVICE_MODEL = "ESP32-C3"
DEVICE_ID = "WATER001"
FW_VERSION = "3.3"
```

流程：

1. 浏览器前端连接 ESP32 BLE 服务。
2. 设备生成 `nonce`。
3. 设备通过 BLE 返回协议名、版本、设备 ID、型号、固件版本和 nonce。
4. 前端计算 `auth = sha256(nonce + SECRET_KEY)`。
5. 前端把 `auth` 随配置 JSON 通过 BLE 写入 ESP32。
6. 设备校验 auth，成功后保存配置到 NVS。
7. 使用过的 nonce 会刷新，避免同一个 nonce 长期复用。

## 设备配置结构

ESP32 通过 BLE 接收的配置主要字段：

```json
{
  "signature": "...",
  "revision": 1,
  "timestamp": 0,
  "configVersion": "1.0",
  "deviceModel": "ESP32-WATER-C3",
  "plant": "...",
  "climateZone": "...",
  "wateringStrategy": "pulse",
  "generatedAt": "...",
  "waterNeedMlDay": 0,
  "country": "...",
  "postalCode": "...",
  "season": "...",
  "source": "api",
  "sourceVersion": "1.0",
  "display": {
    "dailyWaterNeedMl": 0,
    "irrigationMethod": "pulse",
    "plant": "...",
    "source": "api"
  },
  "params": {
    "soilWeight": 0.6,
    "tempWeight": 0.25,
    "airWeight": 0.1,
    "threshold": 50.0,
    "pulseCount": 9,
    "pulseOnMs": 3000,
    "pulseOffMs": 25000
  }
}
```

约束：

- `deviceModel` 必须是 `ESP32-WATER-C3`。
- 新 `revision` 必须大于当前 `g_cfg.configRevision`。
- 权重会归一化并裁剪到合法范围。
- 脉冲参数会按最小/最大值裁剪。

## Flask 临时配置生成格式

前端请求：

```http
POST /api/configurations/generate
```

返回结构建议：

```json
{
  "status": "ok",
  "source": "api",
  "storage": "temporary",
  "config": {
    "deviceModel": "ESP32-WATER-C3",
    "configVersion": "1.0",
    "plant": "...",
    "country": "...",
    "locationName": "...",
    "generatedAt": "..."
  },
  "params": {
    "soilWeight": 0.6,
    "tempWeight": 0.25,
    "airWeight": 0.1,
    "threshold": 50.0,
    "pulseCount": 9,
    "pulseOnMs": 3000,
    "pulseOffMs": 25000
  }
}
```

> [!warning] 字段命名不统一
> 主固件配置使用 `soilWeight`、`threshold`、`pulseOnMs`。后端临时配置生成接口也应优先使用同一套字段，避免再引入 `soil_weight`、`demand_threshold`、`pulse_on_ms` 等额外命名。

## 2026-09-09 网页首版协议状态

网页首版采用本页的规范设备配置结构（`deviceModel: ESP32-WATER-C3`、`revision`、`params`），并使用 SWS-BLE 1.0 握手。`configVersion` 固定为字符串 `1.0`，不再混用数字版本。旧 `device/user/algorithm/watering` 结构保留为历史参考，尚未与实际固件建立转换。

> [!warning] 传输草案不等于实物支持
> 实际服务 UUID、特征 UUID、签名派生规则与固件源码尚未提供。前端暂实现 `sws-json-v1-draft`：带消息 ID 的 JSON 请求、分包序号／总数、CRC32、Base64 数据片段和换行重组。完整契约在项目的 `prototype/docs/ble-protocol.md`；须实物联调后才能确认与现有固件兼容。

只有固件明确返回 `saved: true` 且 revision 一致，网页才显示写入成功；收到保存回执后若状态刷新失败，保留已保存结果并提示重连。模式切换、重启、恢复出厂采用设备确认令牌二次确认。参见 项目中的 `prototype/docs/网页首版实现记录.md`。
