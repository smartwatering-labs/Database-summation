# 具体要求

## 网页目标

网页是用户使用浇水系统的主要入口，采用前后端分化结构。前端负责连接设备、展示状态、收集用户输入和发起配置操作；后端负责资料库查询、第三方 API 调用、参数解算、临时配置生成和系统监控。

网页需要完成三件事：

1. 为 ESP32-C3 提供初始指导资料包，并在蓝牙握手成功后把个性化配置写回单片机。
2. 查询单片机当前采样数据和一周以内的历史数据。
3. 展示产品介绍和基本操作指导。

## 网页体系分层

当前资料中需要区分网页平台、浏览器前端与 ESP32 固件：

- Flask 网页平台：运行在电脑/服务器上，用于接收当前页面提交的场景、推导参数、生成临时配置包和提供系统健康监控。
- 浏览器前端：面向普通用户，首页提供硬件展示和三项快速跳转，子页面分别对应产品介绍、个性化库编译、硬件情况查看，并通过 BLE 与 ESP32 通信。
- ESP32 固件：负责采样、控制、BLE 通信、本地配置保存和历史记录保存。

## 蓝牙连接与配置下发

网页需要支持用户设备与 ESP32-C3 的蓝牙连接：

1. 识别可用蓝牙设备，并与目标设备建立连接。
2. 连接后执行握手，确认设备 ID、固件版本、协议版本和 nonce。
3. 解码芯片传来的数据，转换为网页可展示字段。
4. 将用户输入与后端知识库、第三方 API 返回标签进行匹配。
5. 将后端处理后的配置数据编码、认证、必要时加密，再发回 ESP32。

后端不直接连接 ESP32，也不直接参与 BLE 通信。后端只生成配置并返回给前端；前端通过 BLE 发给 ESP32。蓝牙链路是当前资料中的主交互方式，页面设计应优先表现蓝牙连接状态。

## Flask 平台要求

后端平台负责把“用户场景”变成“设备可用配置数据包”：

1. 接收当前页面提交的植物、地点、花盆、光照、水源、无人值守等场景信息。
2. 调用参数推导引擎得到权重、阈值、脉冲参数、续航估算。
3. 生成可由前端通过 BLE 下发给 ESP32 的配置数据。
4. 维护植物、栽培方式、地区环境等权重库。
5. 调用第三方 API 补充海拔、平均降水量、平均湿度、平均日照时长等资料，并把返回数据标签匹配到用户填写内容。
6. 提供管理员系统监控接口，用于判断后端服务是否正常。

用户提交内容和生成配置只作为当前页面会话的临时数据使用，不做用户登录系统，不保留配置历史版本。用户退出浏览器或关闭当前页面后，前端应清除当前配置状态；后端不把这些配置作为长期用户档案保存。

## 离线与在线能力

- Flask 平台天气 API 可选；没有 API key 或联网失败时，会降级到静态地点数据。
- 第三方 API 可以优先评估 Open-Meteo；如继续使用 OpenWeatherMap，需要明确 key、字段映射和失败降级策略。
- ESP32 不以持续联网为前提；配置由前端通过 BLE 下发，设备运行数据不上传后端。

## 用户体验要求

- 用户应能从网页选择植物和地点，而不是手写参数。
- 个性化库编译页面应采用类似 iOS 设置的面板结构，按信息类别组织输入项和设备操作。
- 分析结果应解释推荐浇水周期、单轮水量、续航天数和推荐模式。
- 配置生成后应能预览、导出，并通过 BLE 下发给 ESP32。
- 对设备侧配置而言，应清楚显示是否已配置、当前配置版本和本次下发结果。
- 首页需要展示可自由转向的 Three.js 硬件 3D 模型；模型未完成前可临时使用图片。
