## Flask 平台 API

| 方法         | 路径                                   | 用途                 |
| ---------- | ------------------------------------ | ------------------ |
| `GET`      | `/`                                  | 返回前端页面。            |
| `GET`      | `/api/locations`                     | 获取地点知识库列表。         |
| `GET`      | `/api/plants`                        | 获取植物知识库列表。         |
| `GET`      | `/api/weather`                       | 获取天气，失败时用静态地点数据降级。 |
| `GET`      | `/api/environment`                   | 按地点查询海拔、降水、湿度、日照等环境资料，可由 Open-Meteo 等第三方 API 支撑。 |
| `POST`     | `/api/configurations/generate`       | 根据当前页面提交的用户场景生成临时个性化配置包。 |
| `POST`     | `/api/configurations/export`         | 将前端当前持有的配置导出为文件或 JSON。 |
| `POST`     | `/api/configurations/import`         | 校验前端导入的配置内容。 |
| `GET`      | `/api/admin/health`                  | 管理员查看后端健康状态。 |
| `GET`      | `/api/admin/stats`                   | 管理员查看系统统计信息。 |
| `GET`      | `/api/admin/logs`                    | 管理员查看系统运行日志。 |
| `GET`      | `/static/<filename>`                 | 静态文件。              |

## Flask 数据库表

| 表                 | 用途             |
| ----------------- | -------------- |
| `plant_weight_library` | 不同植物的权重、阈值和标签资料。 |
| `environment_weight_library` | 不同地区、栽培方式和环境条件的权重资料。 |
| `system_logs` | 后端系统维护日志、错误记录和外部 API 降级记录。 |

用户配置不作为长期数据库记录保存。`/api/configurations/generate` 返回的配置只服务当前页面会话；用户退出浏览器或关闭当前页面后，配置状态应删除。由于不做登录系统，第一阶段不建立 `Users`、`Devices`、`Sessions`、`Configurations` 历史版本表。

## 网页蓝牙能力

浏览器前端需要通过 Web Bluetooth 或等价桥接层访问 ESP32-C3。前端动作包括：

| 动作 | 用途 |
|---|---|
| 发现设备 | 扫描并识别浇水硬件蓝牙信号。 |
| 握手 | 确认设备 ID、固件版本、协议版本和 nonce。 |
| 读取实时数据 | 更新硬件情况查看页面的数据面板。 |
| 读取历史数据 | 获取一周以内历史采样记录。 |
| 写入配置 | 将后端生成的个性化配置包发回 ESP32。 |
| 设备操作 | 切换模式、重启、恢复出厂、导入导出配置。 |

BLE 操作由前端与 ESP32 直接完成，后端不直接连接 ESP32，也不保存 BLE 握手日志或设备传感器历史。

## ESP32 BLE 操作

浏览器前端通过 BLE 与 ESP32 交互，建议抽象为以下操作：

- 握手：返回协议、版本、设备信息和 nonce。
- 读取当前状态：返回设备模式、配置摘要和最新采样数据。
- 读取历史记录：分批返回一周以内采样记录。
- 写入配置：校验 auth、协议版本、设备型号、revision 和参数范围后写入 NVS。
- 设备操作：切换模式、重启、恢复出厂等高风险操作必须由固件端二次确认。

## 错误处理方式

常见返回：

- `400`：JSON 无效、设备型号不匹配、协议版本不支持、参数缺失。
- `403`：认证或签名失败。
- `404`：请求的资源或配置不存在。
- `409`：上传的配置 revision 不高于当前版本。
- `500`：配置生成失败、外部 API 异常等内部错误。

配置下发状态建议按以下流程展示：

```text
生成配置 → 前端发送 → ESP32 校验 → 写入成功/失败 → 前端回报后端可选记录
```

若回报后端，只记录系统级结果或错误摘要，不保存传感器历史和用户配置历史。

## 2026-09-09 网页首版实现补充

上述 Flask 接口已在项目的 `prototype/app.py` 实现。新增 `GET /api/settings`，仅返回公开协议版本、演示开关与 BLE UUID，不返回管理员密钥。天气与环境接口使用 `locationId` 查询；管理员接口通过 `Authorization: Bearer <ADMIN_TOKEN>` 访问。

配置导入、导出、生成接口统一使用规范 camelCase 字段；请求体上限 64 KB。用户配置仅在请求中临时处理，不保存用户配置历史。完整请求示例与上游映射见项目的 `prototype/docs/api.md`。

设备通信属于待实物联调的前端适配层，不属于 Flask API 已验证范围。参见 项目中的 `prototype/docs/网页首版实现记录.md`。
