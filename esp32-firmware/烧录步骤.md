# ESP32-C3 固件上传详细步骤

本文适用于项目根目录 `esp32-firmware/` 中的固件 3.8.0。推荐使用 Arduino IDE 2 图形界面完成第一次上传；熟悉 PowerShell 后也可以使用项目脚本。

## 一、上传前准备

需要以下物品：

- ESP32-C3 开发板；当前工程按项目资料中的板载 72×40 OLED 型号配置。
- 一根确定支持数据传输的 USB 线。只有充电功能的线不会出现串口。
- Windows 电脑和 Arduino IDE 2。

第一次上传时，建议只用 USB 给 ESP32 供电，暂时断开水泵、继电器、电磁阀和其他外部电源。当前固件不会驱动水泵，但这样更容易排除供电、共地和外设接线问题。

固件当前默认硬件参数：

| 项目 | 默认值 |
| --- | --- |
| 芯片 | ESP32-C3 |
| Flash | 4 MB |
| OLED | SSD1306 72×40 |
| OLED 地址 | 0x3C |
| OLED SDA / SCL | GPIO5 / GPIO6 |
| 串口波特率 | 115200 |
| 蓝牙名称 | SWS-ESP32C3 |

如果实际 OLED 控制器、地址或引脚不同，应先修改 `ble_oled_pairing\include\board_config.h`，再重新编译和上传。OLED 配置错误不会阻止 BLE 启动。

## 二、安装 Arduino IDE 和 ESP32 支持

已经安装并能编译 ESP32-C3 时可跳到第三节。

1. 安装 Arduino IDE 2，并启动软件。
2. 打开左侧“开发板管理器”，搜索 `esp32`。
3. 找到作者为 **Espressif Systems** 的 `esp32`，安装 **3.3.10**。这是本项目实际编译通过的版本。
4. 打开左侧“库管理器”，依次安装：
   - `NimBLE-Arduino` 2.5.1，作者 h2zero；本项目至少为 2.4.0。
   - `ArduinoJson` 7.4.2，作者 Benoit Blanchon。
   - `U8g2` 2.36.15，作者 oliver。
5. 安装后重启 Arduino IDE，使开发板和库索引重新加载。

如果库管理器只能看到更高的小版本，可先尝试编译；发生 API 不兼容时，从库条目中的版本下拉框切回上面的已验证版本。

## 三、打开正确的工程

1. 在资源管理器进入：

   `C:\Users\bYYYyyL\Desktop\Watering-platform\esp32-firmware\ble_oled_pairing`

2. 双击 `ble_oled_pairing.ino`。Arduino IDE 应同时把此目录作为工程目录打开。
3. 主程序已完整写在 `ble_oled_pairing.ino` 中；它还依赖同目录下的 `include/board_config.h` 和 `include/sws_core.h`，因此不要单独复制 `.ino` 到其他目录。
4. 外层 `esp32-firmware` 目录保存脚本、测试、构建缓存和本地工具，不要在 Arduino IDE 中把它作为草图打开；只打开这一节中的 `ble_oled_pairing` 子目录。

## 四、连接开发板并识别串口

1. 暂时拔下开发板。
2. 在 Arduino IDE 中查看“工具 → 端口”，记住当前端口列表。
3. 使用数据 USB 线连接开发板，等待 Windows 完成设备识别。
4. 再打开“工具 → 端口”。新出现的 `COM` 端口通常就是开发板。选择该端口。

ESP32-C3 可能显示为 USB Serial/JTAG、USB CDC、CH340 或 CP210x 串口，具体名称取决于板载 USB 电路。没有新端口时依次检查：

1. 更换一根确定能传数据的 USB 线。
2. 更换电脑 USB 口，避免无供电的扩展坞。
3. 打开 Windows 设备管理器，查看“端口（COM 和 LPT）”以及带黄色感叹号的未知设备。
4. 如果板子使用 CH340 或 CP210x USB 转串口芯片，安装该芯片厂商驱动后重新插拔。

不要凭记忆选择 COM3、COM5 等端口。每台电脑和每次插入的位置都可能不同。

## 五、设置 Arduino 开发板参数

在 Arduino IDE 的“工具”菜单中设置：

| 菜单 | 选择值 |
| --- | --- |
| Board / 开发板 | ESP32C3 Dev Module |
| USB CDC On Boot | Enabled |
| CPU Frequency | 160MHz (WiFi) |
| Flash Frequency | 80MHz |
| Flash Mode | QIO |
| Flash Size | 4MB (32Mb) |
| Partition Scheme | Default 4MB with spiffs |
| Core Debug Level | None |
| Erase All Flash Before Sketch Upload | Disabled |
| JTAG Adapter | Disabled |

上传速度可先使用默认值。若出现连接不稳定或写入中断，将 `Upload Speed` 改为 `115200` 后重试。

`Erase All Flash Before Sketch Upload` 默认保持 Disabled，这样更新程序不会主动清除已经保存的 NVS 配置。需要清配置时优先使用网站中的“恢复出厂设置”。只有 NVS 明显损坏且普通恢复失败时，才临时启用全擦除；全擦除会删除设备上原有的所有持久化数据。

## 六、先编译，再上传

1. 点击左上角“验证/编译”按钮。
2. 等待底部输出出现类似：

   `Sketch uses ... bytes (58%) of program storage space.`

3. 若提示找不到 `NimBLEDevice.h`、`ArduinoJson.h` 或 `U8g2lib.h`，返回第二节安装对应库。
4. 编译成功后确认右下角或顶部仍显示正确的 ESP32-C3 和 COM 端口。
5. 关闭 Arduino 串口监视器，也断开网站上已有的 BLE 连接。
6. 点击“上传”按钮。
7. 等待输出完成写入和校验。看到 `Leaving...`、`Hard resetting via RTS pin...` 或 Arduino 显示“上传成功”即表示写入完成。
8. 如果板子没有自动重启，短按一次 `RST` / `RESET` / `EN` 按钮。

上传会替换 ESP32 当前运行的应用程序。它不会修改电脑上的网站文件。

## 七、卡在 Connecting 时进入下载模式

先确认选中了正确端口、串口监视器已关闭。如果仍反复显示 `Connecting...` 或 `Failed to connect`，再手动进入下载模式：

1. 按住开发板上的 `BOOT` 按钮；有些板子标记为 `0` 或 `GPIO9`。
2. 保持按住 BOOT，短按并松开 `RESET` / `RST` / `EN`。
3. 松开 BOOT。
4. 立即重新点击“上传”。

部分板子需要在 Arduino 输出 `Connecting...` 时继续按住 BOOT，看到开始写入百分比后再松开。没有 RESET 按钮时，可按住 BOOT、拔插 USB、等待一秒后松开，再上传。

上传完成后短按 RESET，让设备退出下载模式并运行新固件。

## 八、通过串口确认固件启动

1. Arduino IDE 打开“工具 → 串口监视器”。
2. 波特率选择 `115200`。
3. 短按开发板 RESET。
4. 正常启动时会看到类似：

```text
SWS 3.8.0 device=C3-xxxxxxxxxxxx OLED=found I2C=5/6 address=0x3c
```

含义：

- `device=C3-...`：根据芯片 MAC 生成的设备 ID。
- `OLED=found`：在 0x3C 找到屏幕。
- `OLED=missing`：未找到屏幕；BLE 仍会继续启动，需要检查控制器、地址和引脚。
- 后续 `SWS stage=...`：连接、认证、校验和保存阶段。

如果串口完全没有输出，检查波特率、端口和 USB CDC On Boot。若上传成功但每次复位后端口发生变化，请在新出现的 COM 端口上重新打开监视器。

蓝牙启动与连接过程还会打印以下行，排查连接问题主要看它们：

```text
BLE_SECURITY profile=development bonds=0
BLE_READY SWS-ESP32C3
BLE_CONNECTED handle=1
BLE_AUTH handle=1 encrypted=1 bonded=1 authenticated=0
BLE_DISCONNECTED handle=1 reason=5
```

- `profile=development`：未供应密钥，写入不需要加密，也不需要配对。
- `profile=hmac-sha256-v1`：已供应密钥，写入要求链路加密，必须完成配对。
- `bonds=N`：设备端已保存的配对数量；系统仍显示“已配对”而设备连不上时，串口发送 `BONDCLEAR` 清空后重新配对。
- `BLE_CONNECTED` 完全没有出现：链路层没连上，问题在电脑蓝牙栈或广播，不在协议。
- `BLE_DISCONNECTED reason=5`（密钥缺失）或 `reason=6`（认证失败）：两边保存的配对密钥不一致。
- 每次尝试都先出现完整启动横幅：芯片在复位，优先查供电，不要继续调协议。


## 九、检查 OLED 和蓝牙

板子正常启动后，OLED 顶行应显示：

```text
蓝牙:未连接
```

接着验证网页通信：

1. 回到项目根目录，双击 `prototype\start.bat`。
2. 使用桌面版 Chrome 或 Edge 打开 `http://127.0.0.1:5000`。不要使用普通 `file://` 页面测试 Web Bluetooth。
3. 在网站点击“连接设备”。浏览器设备列表中选择 `SWS-ESP32C3`。
4. 连接成功时 OLED 顶行改为“蓝牙:连接”，其余行依次进入等待认证、等待数据包状态。
5. 在“个性化库编译”页面生成配置，点击原位置的“发送刚生成的配置”。
6. OLED 应显示接收分包数量、校验保存状态，然后约 18 秒轮播配置中的数字。
7. 网站必须收到 `saved: true` 且 revision 一致后才会提示保存成功。

浏览器选择列表中没有设备时：

- 确认 OLED/串口表明固件已经运行，而不是仍处于下载模式。
- 打开 Windows 蓝牙，但不要预先在系统设置中配对该设备。
- 关闭其他可能已连接此 ESP32 的网页或手机；固件只允许一个客户端。
- 重新给板子上电，刷新网页后由按钮再次打开设备选择器。
- 确认使用 Chrome/Edge 的 localhost 或 HTTPS 页面，并已允许蓝牙权限。

## 十、验证配置断电保存

完成一次配置发送后记录 OLED 或网站显示的配置版本，例如 `R1`：

1. 在网站主动断开设备。
2. 拔下 ESP32 的 USB 电源，等待数秒后重新插入。
3. OLED 应重新进入“蓝牙:未连接”，空闲页仍显示原配置版本 `R1`。
4. 网站重新连接并进入“硬件情况查看”。
5. 点击“从设备读取”，检查植物和参数与刚才发送的配置一致。

这一步通过后，才能确认当前实物的 NVS 在真实断电后能正确读回。项目中的软件测试不能代替这一步。

## 十一、使用项目脚本上传

不想打开 Arduino IDE 时，可以在 `esp32-firmware` 目录打开 PowerShell。

只编译：

```powershell
.\build.ps1
```

列出开发板端口：

```powershell
.\build.ps1 -ListPorts
```

假设列表确认开发板是 COM5，再执行：

```powershell
.\build.ps1 -Upload -Port COM5
```

请把 COM5 替换为实际端口。脚本不会自动猜测端口，也不会在没有 `-Upload` 时烧录。双击 `build.bat` 只负责编译。

如果 PowerShell 阻止脚本执行，可从该目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Upload -Port COM5
```

脚本默认寻找 Arduino IDE 自带的 Arduino CLI。Arduino IDE 安装在其他位置时：

```powershell
.\build.ps1 -ArduinoCli 'D:\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe' -Upload -Port COM5
```

## 十二、常见问题对照

| 现象 | 优先检查 |
| --- | --- |
| `Board esp32:esp32:esp32c3 not found` | 在开发板管理器安装 Espressif Systems 的 esp32 3.3.10 |
| 找不到头文件 | 安装 NimBLE-Arduino、ArduinoJson、U8g2 |
| “工具 → 端口”没有设备 | 数据线、USB 口、设备管理器、CH340/CP210x 驱动 |
| `Access is denied` / 端口被占用 | 关闭串口监视器、其他 Arduino 窗口和占用串口的软件 |
| `Failed to connect` | 选对端口，降低上传速度，按第七节进入下载模式 |
| 写入中途失败 | 上传速度改为 115200，换数据线/USB 口，保持供电稳定 |
| 上传成功但 OLED 黑屏 | 看串口中的 OLED=found/missing；核对 72×40/128×64、SSD1306/SH1106、0x3C/0x3D、GPIO5/6 |
| OLED 正常但网页搜不到设备 | Windows 蓝牙、浏览器、localhost/HTTPS、其他客户端占用、重新上电 |
| 网页提示协议或固件不兼容 | 确认烧录的是此目录固件 3.8.0，网页和固件 UUID/协议没有单边修改 |
| 配置发送失败 | 保持 BLE 连接，查看串口阶段日志；重新连接后读取配置，不要直接假定保存成功 |

## 十三、当前验证边界

烧录成功后能验证 BLE 连接、认证、配置包接收、NVS 保存/读回、OLED 状态、配置数字展示、模式确认、重启和恢复出厂接口。

3.8.0 已接入采样、脉冲保护、日志、角色认证与深睡代码。初次上传后先完成 [标定与接板步骤](README.md)，核对实际负载、停止、供电和断电恢复，再进入 LONGRUN；实物结果在验收记录中登记。
