# ESP32-C3 10-01 整机固件

源码版本 **3.9.0**，协议 **SWS-BLE 1.0**，配置格式 **1.0 / 2.0**。网页生成临时配置，浏览器通过 BLE 下发，设备在本地采样、判断、执行和记录。上电后直接输出温湿度、土壤与雨量 ADC，以及太阳能 ADC 电压。自动运行以 2.0 绑定配置、可信时间、可用存储及有效传感器输入为准。

## 运行流程

| 模式 | 行为 |
| --- | --- |
| DISPLAY | BLE 在线、周期采样；可进行校时、三轮快速检查、主动改变输入的通道检查和短时手动控制 |
| PREPARE | 十分钟采样；直接有效样本至少 10 个且占比至少 80% 时建立逐通道基准；结束回到 DISPLAY |
| LONGRUN | 关键通道有效、需求阈值和最短间隔同时满足后执行非阻塞脉冲；结束记录检查点，断开 BLE 后进入两小时定时深睡 |

浇水前写入并读回尝试检查点。降雨、过期、存储或关键通道异常时关泵；停止、切换模式、重启和休眠执行关闭流程。浇水中更新配置被拒绝。冷启动进入 DISPLAY；中断恢复重新等待完整最短间隔。深睡恢复按实际 RTC 时间差扣减等待时间，校时保持已累计间隔和本轮脉冲时长。

网页手动控制在 DISPLAY 和完成握手认证后可用。舵机按固定参数输出 1600 µs、1500 µs 脉宽，各持续 500 ms，完成一次小幅往返；水泵与舵机互斥。本机 SIGS1↔SIGS2 排线为反接状态，固件把泵/舵机输出对调：水泵由 GPIO2 高电平开启、低电平关闭，舵机使用 GPIO7；网页读取设备回执与状态后才切换按钮；30 秒后自动关泵，BLE 断开、模式切换、停止与重启也会关泵。动作回执表示命令执行状态，实际转动和出水需现场确认。

## 引脚和采样

GPIO0 为传感器供电，GPIO1 为太阳能 ADC，GPIO2 为水泵（本机反接映射，高电平开泵），GPIO3 / GPIO4 为雨量 / 土壤 ADC，GPIO5 / GPIO6 为 OLED，GPIO7 为舵机（本机反接映射），GPIO10 为 DHT11 / DHT22。若把 SIGS 排线改回针1对针1，需同步把 `board_config.h` 的 `SWS_PUMP_PIN` / `SWS_SERVO_PIN` 改回 7 / 2，否则泵和舵机会再次对调。

传感器上电等待、DHT 起始脉冲、五次 ADC 中位数和舵机动作由主循环分阶段执行。DHT 捕获采用有上限的微秒等待。固定参数位于 `include/board_parameters.h`：默认 DHT11、上电等待 2000 ms、两次采样之间等待 2000 ms、太阳能分压比例 0.2。主采样字段直接保留 DHT 读数、土壤与雨量 ADC（包括 0 / 4095），太阳能 ADC 电压以 mV 输出；DHT 读取失败时对应值为 null。质量状态单独报告跳变、读数失败及输入异常，异常数字仍保留供查看；自动控制使用通过质量检查的数据。温湿度每次重新读取。

自动需求值以土壤 ADC / 4095 形成相对输入，结合配置中的土壤、温度和空气权重及阈值计算；不代表土壤湿度百分比。固定有雨判据为雨量 ADC 小于 1000；土壤或雨量 ADC 小于 16、大于 4079 时暂停自动浇水，原始值照常输出。配置中的脉冲次数、开泵时长、关泵间隔和最短浇水间隔继续由网页客制化配置决定。流量沿用知识库或用户填写值，用于网页水量计算。

OLED 默认 SSD1306 72×40、0x3C，显示 BLE、当前采样、准备期和脉冲进度。

## 构建

Arduino ESP32 核心 3.3.10；NimBLE-Arduino 2.5.1、ArduinoJson 7.4.3、U8g2 2.36.19。NimBLE 至少为 2.4.0，使用服务器启动 API，并包含 Arduino 核心 3.3.7 及后续版本的初始化修复；构建脚本优先使用 Arduino 库管理器安装的兼容版本。LittleFS、ADC、LEDC 与睡眠接口使用核心附带实现。

- build.ps1：缓存构建；加 -Clean 完整重建。
- build.ps1 -ListPorts：查看实际端口。
- build.ps1 -Upload -Port COM5：明确选择端口后上传。
- tests/test-firmware.ps1：原生运行控制及网页/固件协议测试。

构建清单记录 NimBLE 版本、全部固件源文件及二进制 SHA-256，并检查编译前后源码一致。原生工具链从项目缓存恢复到 .tools/native-gcc。菜单及端口操作见 [烧录步骤](烧录步骤.md)。

## 接板后的配置顺序

1. 核对 10-01 接线、USB 并供和负载。首次采样先断开泵与舵机负载，确认 GPIO 与 ADC。
2. 串口 115200，发送 IDENTITY 核对设备 ID，发送 SAMPLE 读取当前采样 JSON。
3. 初次使用日志分区，在 DISPLAY 发送 LOGFORMAT；它清空 LittleFS 日志，保留 NVS 配置和身份。
4. 网页写入 2.0 绑定配置、校时、快速检查及十分钟 PREPARE；有效准备期温湿度报告可用于重新生成种植配置，流量来源保持为知识库或用户输入。
5. 完成负载、停止、断电和深睡检查后进入 LONGRUN，开展一周连续运行验收。

串口 WIPE 在 DISPLAY 执行固定参数的舵机往返，返回 WIPE_STARTED 或 WIPE_UNAVAILABLE；STOP 进入关闭流程。网页的独立单字节 ! 停止通道会中断普通分包，关泵并清除旧请求，返回停止回执，再重新握手核对状态。

水泵命令执行后，串口输出 `PUMPSTATUS`，记录固件版本、GPIO 编号、命令状态、目标电平和引脚逻辑回读。也可在 115200 串口发送 `PUMPSTATUS`，只读取当前状态。本机 SIGS 反接，泵输出重新分配为 GPIO2，因此 `pin=2`；当前高电平有效：开泵预期为 `on=1 commandedLevel=1 pinLevel=1`，关泵预期为 `on=0 commandedLevel=0 pinLevel=0`。回读仅表示 ESP32 GPIO2 上的逻辑电平，不能证明下板收到信号或水泵实际转动。上板物理断开后的下板默认状态由下板电路决定。

## 保存和时间

NVS 分别保存配置、尝试检查点、准备期基准和设备身份。配置及运行记录含 CRC 与回读检查；基准按配置版本保存，恢复采用二十四小时内的可信记录。

LittleFS 采用两个轮换槽、序号、记录数和逐字节 CRC；写后逐条回读，启动选择最新有效槽。历史上限 168 条 / 48 KiB，事件上限 48 条 / 20 KiB。每分钟、检查点及休眠前保存；泵开启期间延后日志写入。每页最多 24 条，同时按 UTF-8 大小缩小页面。可信时间的一周筛选由网页执行；未校时使用启动和采样序号。

准备期报告记录各通道有效/失败次数、均值、极值、最大单次变化及采样时段，基准按设备与配置版本保存。配置中的已审核温湿度范围以至少一分钟间隔连续三次偏离后记录提示，事件包含参考范围与实测摘要；连续三次恢复后更新恢复时间。快速检查是三轮采样，受刺激检查要求操作人实际改变选定通道的输入。校时记录 lastSyncAt，网页以一次 BLE 往返测量估算传输延迟。

## 独立设备密钥

未供应密钥时使用开发认证。tools/provision_identity.py 通过明确的 USB 端口和设备 ID 供应 256 位随机密钥，并把所有者凭据保存到本机指定的新文件。已有密钥需明确加 --rotate，原凭据保留用于结果核对。可分别供应 operator 和 viewer 凭据，按角色限制配置修改、运行操作和数据读取；通过 USB 撤销或轮换角色凭据。首次供应所有者密钥后重启设备，使 BLE 写入特征启用链路加密要求。

密钥设备声明 hmac-sha256-v1：先验证设备证明，再验证客户端证明；后续请求、进度和回执按会话 nonce、序号和原始消息体进行 HMAC 校验，拒绝重放和篡改。认证配置上限 4000 UTF-8 字节。网页与离线入口主动导入凭据，只在当前页面内存使用。恢复出厂保留身份，清除配置和运行记录。

HMAC 提供身份及完整性；拥有所有者密钥的设备要求 BLE 写入链路加密，使用无输入输出配对方式。NVS 密钥仍需结合 Flash 加密及物理访问控制评估。详见 prototype/docs/device-authentication.md。

配对记录可在串口管理：`BONDS` 打印设备端已保存的配对数量，`BONDCLEAR` 清空全部配对，`KEYCLEAR` 删除所有者密钥并连同 `nimble_bond` 命名空间一起清空、回到 development 开发认证（配置与日志保留），重启后生效。配对中断可能留下删除 API 清不掉的残缺记录（`BONDS_CLEAR_FAILED` 且 `bonds` 不归零），此时用 `KEYCLEAR`。要让电脑彻底遗忘这台设备，递增 `ble_oled_pairing.ino` 中的 `SWS_BLE_ADDR_SALT` 换一个新的 BLE 地址即可；设备 ID 不变。

## 实物验收

`tools/verify_ble.py` 使用已有所有者凭据检查设备证明、互认证、签名状态、配置、事件和历史，记录实际 MTU、协商分块容量及操作耗时。它执行读取流程，适用于重新上电后的连接检查。环境需要 bleak；诊断输出只包含核验结果和业务参数。关闭浏览器中的现有设备连接后，在本目录执行：

```powershell
python tools/verify_ble.py --address D4:05:92:E6:DE:CE --credential credentials/C3-ccdee69205d4-owner.json --output .tools/ble-verification-new.json
```

地址和凭据须对应目标板，输出路径须为新文件。设备握手前采用 20 字节写入，之后按设备声明的 MTU 容量传输，最多 244 字节；较小 MTU 保持兼容。此诊断通过表示所列 BLE 操作通过，完整整机验收还包括下述实物项目。

主机测试使用相同协议核心与运行状态机。DHT 时序、ADC、电气负载、GPIO 保持、Flash 断电、深睡漂移和出水量须在 ESP32-C3 上完成。当前构建清单 physicalHardwareVerified=false；完整完成记录与接板检查见 files/改进方案/2026-10-14完成情况与接板验收.md。
