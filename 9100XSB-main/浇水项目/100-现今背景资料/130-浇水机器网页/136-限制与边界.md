## 蓝牙链路限制

- 浏览器蓝牙能力受系统、浏览器和用户授权影响，不应假设所有设备都支持。
- Web Bluetooth 兼容性提醒先放在首页，备用方案暂时不定。
- ESP32 deep sleep 后蓝牙连接会断开，网页需要能自动提示重连或重新握手。
- ESP32 deep sleep 时 BLE 不工作，网页不能远程唤醒设备；用户必须通过外置按钮唤醒后再连接。
- 一周历史数据可能超过单次蓝牙传输能力，需要分包、分页或压缩。
- 配置下发必须在固件端二次校验，网页端校验只能作为用户体验辅助。
- 若使用加密或签名，应明确密钥来源、nonce 过期、重放防护、配置签名方式和失败提示，不宜只依赖前端隐藏字段。
- 设备侧交互集中在 BLE 读写能力上，浏览器页面由前端项目提供。

## Flask 平台限制
- 第一阶段不做用户登录系统，不保存用户配置历史，也不建立用户、设备、会话表。
- 用户配置只作为当前页面会话临时数据；用户退出浏览器或关闭当前页面后删除。
- 天气/环境接口可能依赖第三方服务。Open-Meteo 可作为优先候选；外部 API 失败时必须降级到静态地点库，并在结果中标记 `source: fallback`。
- 后端权重库本身需要版本标识，否则同一用户输入在不同时间可能生成不同配置且难以追溯。
- 后端系统日志可以保存服务错误、外部 API 降级、接口耗时等维护信息，但不保存传感器历史和用户配置历史。
- 管理员密钥 `6767` 只允许作为开发期临时方案，不作为最终安全方案。

## 协议限制
- 认证 secret 写在固件中，不适合高安全要求场景。
- 主固件签名逻辑较简化，需要进一步确认安全性。
- 配置字段存在命名不统一问题。
- 配置版本、固件版本、协议版本需要分开管理，不能混用。

## 用户操作边界
- 网页平台推导出的参数是建议值，不保证适合所有土壤和水泵。
- 关键参数必须在固件端二次校验。
- 修改脉冲次数、开泵时间、继电器电平等参数前，应先确认硬件安全。
