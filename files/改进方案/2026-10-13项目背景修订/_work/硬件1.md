# 浇水平台传感器采样与自主运行方案
修订日期 2026年10月13日  文档编号 硬件1

本方案将10-01硬件接入ESP32-C3固件，形成采样、准备期统计、浇水保护、环境提示和时间记录的运行流程。实施包括编写固件、编译、USB烧录以及串口、OLED和BLE真机验证，供后续拆分开发任务使用。

## 一 当前基础与开发目标
当前3.4.0固件提供BLE通信、OLED显示和NVS配置保存，支持DISPLAY与PREPARE状态。真实采样、准备期计时、自动浇水、LONGRUN和历史记录是本次新增能力。目标模式沿用现今需求：DISPLAY约每2秒采样，PREPARE默认10分钟，LONGRUN默认每2小时唤醒；具体采样周期随传感器型号和标定结果确定。
Flask根据公共知识库、场景和天气生成临时配置，浏览器经BLE下发，设备校验保存后独立运行。植物知识库由后端维护；配置、校准、运行检查点和历史由设备按各自生命周期管理。浏览器连接已唤醒设备后读取状态及记录。

| 任务 | 现有基础 | 本次工作 |
| --- | --- | --- |
| HW1 01 P0 | 10-01引脚资料及通信固件 | 真实采样、执行器保护和自主控制 |
| HW1 02 P1 | PREPARE状态及准备期需求 | 准备窗口、有效样本统计与基准 |
| HW1 03 P1 | 植物需水参数及地点天气 | 审核范围下的环境偏离提示 |
| HW1 04 P2 | 天气辅助生成配置 | 可靠实测摘要辅助重新生成 |
| HW1 05 P1 | 固定传感器通道 | 质量状态、失败确认、降级与恢复 |
| HW1 06 P1 | 开机活动计时 | 跨休眠时基、BLE校时和时间质量 |

P0为自动浇水准入前置；P1完善诊断和使用流程，其中关键通道质量与时基保护需随基础控制完成；P2独立安排。自动浇水启用前，要完成新板传感器标定、泵与舵机负载测试，以及硬件2的保存和恢复验证。

## 二 HW1 01 真实采样与浇水控制
固件目录为esp32-firmware/ble_oled_pairing，入口为ble_oled_pairing.ino、include/board_config.h及include/sws_core.h。扩展Platform的采样、执行器和调度接口，传感器、控制、质量判断与存储分别实现为模块，保留已有BLE接收队列和串行处理。

| 通道 | 10-01引脚 | 实现要点 |
| --- | --- | --- |
| 传感器电源 | GPIO0 | 高电平开启，初始化及采样结束关闭 |
| 太阳能电压 | GPIO1 | 按实测分压和校准毫伏换算 |
| 雨量与土壤 | GPIO3与GPIO4 | ADC读取，分别标定方向、范围与阈值 |
| DHT温湿度 | GPIO10 | 核实型号，按读取间隔与上电要求采样 |
| 舵机与水泵 | GPIO2与GPIO7 | PWM与MOS控制；GPIO7低电平关泵 |
| OLED | GPIO5与GPIO6 | 保留72×40显示和独立启动状态 |

采样按关泵初始化、开启传感器电源、等待稳定、滤波读取、质量检查、关闭电源执行。输出通道值、单位、原始读数、采样身份和质量；未配置通道返回空值及原因。断电期间释放信号线，实测回灌与ADC输入量程。
控制采用非阻塞状态机安排泵脉冲、舵机动作和等待，持续服务BLE与停止请求。舵机的供电、收尾位置和擦拭稳定时间分别验证。供水量依据实测流量估算，太阳能通道按输入电压展示。
自动浇水同时检查有效配置、标定、土壤与雨量质量、最短间隔及单轮上限。有雨、关键通道失效、异常退出、复位和睡眠前保持关泵。最短间隔新增为可执行控制字段，与网页1同步生成、校验和版本迁移；display.estimatedIntervalDays继续用于展示。
验收记录原始ADC、实际电压、干湿端点、稳定时间、泵流量和舵机行程。分别测试单负载、联合负载、停止、复位及异常收尾，核对串口、OLED和BLE结果。

## 三 HW1 02 准备期统计与基准
准备期默认10分钟，泵保持关闭，可中止或重新开始。5分钟快速检查作为可选子阶段；每3秒一次可用于初期采样实验，最终周期按DHT型号、上电稳定时间和ADC滤波确定。
按通道统计有效数、失败数、均值或中位数、极值、波动和时段。上电稳定、雨量擦拭及主动环境变化分别标记；样本不足返回“基准未建立”。基准关联deviceId、配置revision、通道和起止时刻。
温湿度基准用于比较安装位置与区域天气。土壤端点及雨量阈值通过独立干湿实验标定。验收覆盖有效、部分失败、全部失败、中止与重启，确认旧基准在设备或配置变化后得到正确处理。

## 四 HW1 03 环境适配与参考偏差
依赖真实采样、准备期统计以及网页1审核后的植物参考范围。先扩展公共知识库的温湿度范围与适用场景，再向设备发送当前植物需要的范围摘要。
按通道比较有效窗口统计与参考范围，分别设置偏离阈值、持续时间及恢复滞回。温度、空气湿度、土壤ADC和雨量ADC采用各自单位及解释规则；比较时核对测量时段、安装环境和来源。区域天气用于参考，设备读数用于表示安装位置条件。
提示围绕观测结果与检查动作，例如“温度持续超出参考范围，请检查遮阴和种植环境”。缺少审核范围时显示“暂无适配依据”。阈值与持续时间依据传感器精度及样板实验确定。
设备将偏离及恢复写入本地事件。事件带通道、代码、参考范围、实测摘要、质量、配置revision和时间质量；浏览器连接后读取展示。事件格式纳入BLE协议扩展，与网页2共用定义。
验收覆盖范围内、持续越界、边界波动、恢复、缺少参考、室内外差异和断开BLE。用原始样本与事件记录检查触发及恢复条件。

## 五 HW1 04 实测辅助重新生成配置
此项为P2，依赖质量合格的设备测量和网页1的生成契约。用户先查看API与实测的时间、单位、样本数和差异，再选择是否将实测摘要提供给后端重新计算。
新增请求字段、质量校验、来源标识和规则分支。后端在单次请求内处理摘要，生成结果保留来源与版本；公共知识库继续走管理员审核流程。
网页展示新旧参数，确认目标deviceId和当前revision后发送。设备完成校验、NVS写入和回读再使配置生效。预览阶段维持关泵；参数更新采用明确的生效规则，保留当前轮次的配置revision。
自动控制持续执行土壤、雨量、最短间隔和单轮上限保护。无效或过期实测在请求入口拒绝，质量合格的数据按规则参与计算。验收检查来源追溯、质量拒绝、参数对照、公共库版本及保存确认。

## 六 HW1 05 质量判断与降级
质量状态采用有效、疑似异常、无效、过期和未配置。检查读取失败、非有限值和标定范围，再结合连续失败、跳变、卡值及供电状态判断。恒定环境与合法变化通过受控实验纳入判定测试。
原始数据与质量标记共同保留，控制计算使用合格样本。连续异常2至3次可作为实验候选，要明确计数单位、重试关系及恢复条件。事件描述可核对的现象，例如连续读取失败、超范围或疑似土壤通道异常。

| 情况 | 控制和显示行为 |
| --- | --- |
| 土壤或雨量无效、过期 | 关泵并暂停自动浇水，提示检查对应通道 |
| 温湿度短时失败 | 经验证后可使用近期有效值，显示来源和年龄上限 |
| 温湿度持续失败或替代值过期 | 进入待检查状态，按保护规则处理 |
| 太阳能输入异常 | 展示该输入的电压与质量，提示检查测量链路 |
| 多通道同时失败 | 展示共用供电和接线检查步骤，记录待查原因 |
| 连续有效样本恢复 | 满足恢复次数和滞回后更新状态及事件 |

温湿度替代涉及控制权重与固定参数，须先验证该分支。关键通道恢复以有效采样为条件，页面“已查看”只改变查看状态。验收覆盖断线、超范围、重试、恒定环境、合法突变、替代值过期与恢复，核对泵状态和新基准。

## 七 HW1 06 时基与BLE校时
活动期使用单调时间安排采样和泵时序；跨深睡的浇水间隔累计实际经过时间。提前唤醒按实际时长计算。采样记录包含时间来源、可信度、上次校时和唤醒序号；配置timestamp表示生成时间。
新增BLE校时动作，定义权限、单位、往返延迟处理和确认回执。浏览器提供时间时标明来源；校时保持当前泵时序与最短间隔保护。未校时记录按序号排序。
RTC用于跨深睡状态，完全断电恢复依靠硬件2的持久检查点。无法确认间隔已满足时进入安全等待，记录恢复条件。实际按钮接线与C3支持的唤醒引脚在烧录前核实。
验收覆盖定时唤醒、提前唤醒、完全断电、时间前后跳变与多周期漂移。记录活动及休眠时长，达到影响控制的漂移才进入补偿设计。

## 八 开发与烧录顺序
先恢复编译和测试环境，确认C3板型及依赖。第一阶段烧录采样固件，完成传感器标定；第二阶段烧录执行器测试固件，验证负载与保护；第三阶段加入准备期、最短间隔、持久检查点和LONGRUN，完成网页联调。
每阶段运行协议与固件测试，编译输出.bin和构建清单，通过确认的USB端口烧录，读回固件版本、设备ID、能力及配置revision。保留已知构建和校准记录；升级检查分区、NVS及配置迁移。
准入检查覆盖关泵启动、关键通道失效、脉冲上限、断电中断、配置切换和睡眠恢复。通过后安排正常负载连续运行至少一周，记录唤醒、浇水、故障与重启。实物电压、流量和实际关泵由现场测量确认。

## 九 参数与验收证据
样板确认DHT型号、读取周期、电源稳定时间、ADC量程、干湿端点、雨量阈值、擦拭等待、泵流量、舵机行程和唤醒方式。质量规则再确定有效样本下限、失败及恢复次数、替代值年龄、偏离持续时间、历史容量和允许漂移。
当前固件测试工具链缺少bits/c++config.h，构建脚本默认位置未找到Arduino CLI。恢复工具链后重新编译当前源码，构建版本、源文件哈希和二进制哈希共同留档。
交付证据包括源码及协议版本、构建清单、烧录日志、标定记录、故障注入结果和持续运行记录。软件测试、真实Flash断电和电气测量分别验收。
