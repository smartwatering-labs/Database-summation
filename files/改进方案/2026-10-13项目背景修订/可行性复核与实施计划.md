# 浇水平台可行性复核与实施计划
修订日期 2026年10月13日  配套硬件1 硬件2 网页1 网页2修订版

本计划将四份修订方案合并为可拆分的开发任务，区分现有功能的修改和新增能力，并补充复核时发现的控制闭环缺口。硬件任务包括编写ESP32-C3固件、编译、通过USB烧录和真机验证。网页继续负责生成临时配置并经BLE发送；设备独立执行控制。

## 一 复核结论与验证边界
方案在现有ESP32-C3、BLE、Flask和网页架构下具有实施路径，但当前还不能判定整机可靠。主要前置是恢复编译环境、确认新板标定及负载参数、明确唤醒方式，随后完成真实采样和自主运行控制。数据来源审核、生产设备认证和完全离线入口有独立依赖，可以分期完成。

| 复核对象 | 2026年10月13日检查结果 |
| --- | --- |
| 后端现有行为 | 24项单元测试通过，覆盖配置生成、校验、数据库版本、管理接口、地点和天气失败处理。测试使用模拟外部响应，不证明线上API可用率。 |
| 浏览器协议 | 12项协议测试通过，覆盖分包、CRC、容量、确认回执与断线等。不等同于浏览器真机GATT验证。 |
| 固件主机测试 | 未通过编译前置，项目MinGW缺少bits/c++config.h；测试没有执行，不能计为通过。 |
| Arduino固件构建 | 构建脚本默认位置未找到Arduino CLI，本轮未完成重新编译。旧构建文件不能证明当前源码通过。 |
| 真实硬件可靠性 | 本轮未烧录或操作设备，未验证ADC标定、泵和舵机负载、真实Flash断电恢复或长期休眠。 |

后端首次运行因沙箱临时目录导致SQLite无法创建数据库；改用工作区独立临时目录后24项通过。此问题归入测试环境，未修改产品代码。现有3.4.0固件具有BLE、OLED和NVS配置能力，真实sample为空、history为空，LONGRUN及自动浇水尚未实现。

## 二 本轮补充的关键缺口
- 最短浇水间隔必须成为设备可执行的控制规则。现有display.estimatedIntervalDays只是展示字段，不能拿来假定调度已实现；新增字段需同步生成、导入校验、固件校验和版本迁移。
- 固件Platform尚无真实采样、执行器和运行调度契约，需要扩展适配层并实现状态机。水泵脉冲、舵机和采样等待不能用长时间阻塞延时，否则BLE处理和停止控制会被拖住。
- 网页当前每次轮询都会向趋势追加sample，新增采样身份与去重后才能正确区分实际采样频率和页面读取频率。
- 休眠、提前唤醒和完全断电要分别处理。间隔按真实经过时间计算，不按唤醒次数乘两小时，也不把配置生成时间当作已校时证据。

## 四 固件可靠性设计要求
冷启动先关泵；标定、配置或时间不满足条件时保持安全等待。一次浇水开始前保存尝试状态，结束后记录完成；中途断电后不能重复补打完整一轮。供水量按标定流量估算，不能宣称已经测得实际出水量。
计时控制使用单调时基，跨深睡保存必要状态；完全断电后若无法证明最短间隔已满足，就抑制自动浇水并给出恢复条件。浏览器前后调时不改变正在执行的脉冲时长，历史保留时间质量。
新配置不得在正在浇水时改变当前轮次含义；明确拒绝、延迟生效或安全停止后切换的唯一规则。控制事件带配置revision，防止新旧参数与历史混用。
配置、校准、运行检查点与历史分别定义生命周期；历史采用有界记录和写入节流。确定分区后选择一种日志存储实现，不能同时无依据承诺SPIFFS和LittleFS。无有效配置或存储异常时关泵，是否增加双槽由故障注入结果决定。

## 六 联调保持的项目边界
后端生成临时JSON，浏览器BLE下发，ESP32自主运行。网页配置发送和固件USB烧录是两条操作流程。设备无本地网页、SoftAP或HTTP服务；前端不自动增加个人配置及传感器历史持久缓存，后端不增加个人设备历史库。
地点或天气查询失败继续阻止新配置生成。已加载页面中已有的有效配置可测试BLE发送，但刷新后能否打开、导入是否需要后端、浏览器是否支持BLE要分别验收，不能笼统写成支持完全离线。
新增字段按协议能力协商和结构版本兼容；当前上限为业务消息8192字节、配置6144字节、70帧及每帧120字节业务数据。用UTF-8实际大小验收，历史和事件分页，避免把整库塞入配置。
GATT写入成功不代表NVS保存成功。收到saved:true且revision匹配才确认保存；回执缺失显示未确认，重连读回，避免自动重放写入。公开开发口令与MAC设备ID不能宣传为生产防伪认证。

## 八 每次固件阶段的具体流程
先运行协议与固件单元测试，再用明确的C3板型和固定依赖编译，检查Flash和RAM用量，输出.bin及构建清单。烧录前关闭占用串口的监视器，确认设备和端口，随后使用本地Arduino工具通过USB上传；不从网页进行代码烧录。
保留可恢复的已知构建、配置和校准记录。升级前检查分区是否变化、是否擦除NVS和新旧配置迁移；恢复旧固件时也检查配置结构兼容，不能把旧.bin存在当作必定可回退。
烧录后核对串口启动信息、设备ID、固件版本、能力、配置revision及安全模式，再通过OLED与BLE确认。版本号按实际发布递增，不把计划阶段名称或旧清单里的3.4.0当作新构建结果。
编译和自动测试可以在电脑上完成；烧录、接线、万用表及流量测量需要实际连接的板子，不能远程读取的部分由现场测量配合。未来进入执行任务时记录每次烧录端口、二进制哈希、配置与测量结果。

## 九 真机验收与准入标准
以下是计划中的最低检查项，需保留版本、板型、供电、操作步骤和实际结果。所有数值容差先通过标定和需求确定；不能把以下检查清单直接标为已通过。

| 场景 | 必须观察到的行为 |
| --- | --- |
| 上电、复位、睡眠前 | 泵保持关闭，GPIO7及实际负载状态符合安全设计；OLED启动失败不阻断BLE和保护流程。 |
| 传感器上电与断电 | 稳定后读取，断电无明显回灌；ADC输入电压在设置量程内，原始值与毫伏记录对应。 |
| 土壤或雨量断线、过期 | 自动浇水被抑制，状态和事件说明通道原因；不能用历史均值冒充当前值。 |
| DHT失败、真实环境变化 | 区分读取失败与正常变化；替代值有来源和年龄，过期后停止使用，恢复有明确规则。 |
| 水泵、舵机联合负载 | 无意外复位，供电及动作符合要求；BLE仍能响应，停止后实际关泵。缺少电流与流量反馈时只报告控制命令和观察结果。 |
| 脉冲与最短间隔 | 边界配置不超过单轮上限；多次提前唤醒和校时不让浇水提前；完成与中断分别记录。 |
| 真Flash断电试验 | 保存前后、分包中、写入附近和回执前断电，重新上电读回配置及revision；读回失败时进入安全状态。 |
| 浇水期间断电 | 重启不补打一整轮，明确记录中断或结果未知；没有可信间隔证据时不立即再次浇水。 |
| 深睡与时间 | 正常定时唤醒、现场唤醒和断电恢复分别验证；多个周期测漂移，未校时历史无伪精确日期。 |
| 双设备与保存回执 | A生成后切换B不误写；迟到响应不串台；回执丢失先读回，不自动重放。 |
| 轮询和协议容量 | 同一采样重复读取只画一个点；重启后的序号不碰撞；新配置和日志分页不越界，旧固件拒绝不支持的能力。 |
| 断网与持续运行 | 区分后端、天气和BLE错误；正常负载连续运行至少一周，事件记录覆盖异常且容量与写入策略符合设计。 |

故障注入先在可控条件下分步进行。涉及电压、接线、负载和物理关泵的判断，需要现场观测；软件注入无法证明实物电气保护。出现意外复位、泵误开、配置读回不一致或保护绕过，暂停自动运行并修复后重验相关场景。

## 十 必须实测或确认的参数
需确认DHT型号及读取间隔、电源稳定时间、土壤干湿端点、雨量方向及擦拭等待、太阳能最大输入和分压、泵流量、舵机行程、空载与联合负载电压、现有按钮接线。
ADC按校准毫伏与实测分压换算。C3官方11dB档可测范围约0至2500mV，量程不等于电气极限；不用raw乘3.3除4095，也不移植旧土壤15和5等数值。
GPIO0至5已有用途，不随意用GPIO8或9做深睡唤醒。核实按钮连接EN、BOOT或唤醒引脚，分别处理复位与唤醒；计时唤醒API按实际核心版本实现。

| WEB2 01能力和连接展示 | W4，按当前与未来固件能力分别展示。 |
| WEB2 02异常视图 | W4接入F3、F4、F5事件，不虚构遥测输入。 |
| WEB2 03握手与保存闭环 | W3，与HW2 01复用同一任务。 |
| WEB2 04安全说明与生产扩展 | W5当前说明，F5和W6生产扩展。 |

后续交付任务建议先按F0、F1、F2加W2、F3、F4加W4、其余P1、P2排序。每项任务写清现有入口、待增加模块、依赖、参数、测试、烧录条件和实际验收证据。优先交付能够稳定运行的基础固件，再增加环境解释和独立增强。
